# TraceLens

TraceLens is a full-stack personal project by Jatin Sharma: a supply-chain impact workspace built around product passports, supplier relationships, evidence records, impact estimates, and a grounded AI analyst. It draws on the technical domains in Jatin's resume, while remaining a separate project and not company work.

## What works

- Angular dashboard reads live API records and calculates portfolio metrics, supplier rollups, and material impact charts from those records.
- Product records can be created, searched, viewed, edited through the API, and deleted. Evidence records can be attached to a product passport.
- The Express API validates input, rate-limits requests, sets security headers, and protects workspace changes behind owner sign-in.
- First-run owner registration requires the private `WORKSPACE_PASSWORD` setup key. Only one owner account can be created; email/password credentials are stored in MongoDB with a salted scrypt hash, and registration closes automatically afterward.
- MongoDB/Mongoose persistence is included. The Docker setup stores data in a named database volume.
- The AI endpoint retrieves product and evidence records on the server. With `OPENAI_API_KEY`, it calls the configured model; without a key it returns clearly labeled rule-based answers based on the same workspace records.
- Optional Climatiq factor search and estimate endpoints can calculate and save a footprint using a selected factor and activity parameters.
- Sample values and supplier evidence are fictional and labeled illustrative. They are not measurements, certifications, or verified supplier audits.

## Run the complete app locally

Requires Docker Desktop or Docker Engine with Compose. From this directory:

```sh
cp .env.example .env
```

Edit `.env`: set a private `WORKSPACE_PASSWORD` setup key and generate a random `JWT_SECRET` (for example, `openssl rand -hex 32`). Add `OPENAI_API_KEY` for live LLM answers. `CLIMATIQ_API_KEY` is optional. Then start the app:

```sh
docker compose up --build
```

Open http://localhost:4000. The first run creates fictional sample records in MongoDB. Select **Create owner account** and enter the `WORKSPACE_PASSWORD` setup key once, then choose the email and password you will use to sign in. Registration closes after the first owner account is created. Workspace edits persist in MongoDB. To start fresh, stop the services and remove the `tracelens-data` volume; that permanently deletes its stored records.

## Run without Docker

Requires Node.js 20.19+ and npm. Copy `.env.example` to `.env`, configure `MONGODB_URI`, `WORKSPACE_PASSWORD`, and `JWT_SECRET`, then install packages. Start the API with `npm run start:api` and Angular separately with `npm start`. The development server proxies `/api` to port 4000. For a production-style single server, run `npm run build:web` followed by `npm run start:prod`; Express serves both Angular and the API from port 4000.

## Deploy

The GitHub Pages URL hosts a static Angular build, which cannot run the Node API or MongoDB. A [Render Blueprint](https://render.com/docs/blueprint-spec) is included at the repository root to deploy the Docker app. It asks for a MongoDB connection string, an owner password, and an OpenAI API key in Render's secret fields; the JWT secret is generated by the host. Never put these values in GitHub or `runtime-config.js`.

Create a MongoDB database first, then create a Blueprint in Render from this GitHub repository and provide the requested secrets. The portfolio page links to the live Render app. On first use, select **Create owner account** and use the Render `WORKSPACE_PASSWORD` value as the one-time setup key; then choose your sign-in email and password. Registration closes after the first owner account is created. Add `OPENAI_API_KEY` only if you want live model answers; without it, the analyst uses the grounded demo fallback. Add `CLIMATIQ_API_KEY` if you want real factor search and footprint estimates.

For local development or a single-host deployment, the frontend and API share the same origin, so the API base can stay empty. Do not expose the MongoDB port publicly. Keep the one-time setup key private, choose a separate strong owner password, and rotate exposed credentials.

## API overview

- `GET /api/status`, `/api/analytics`, `/api/products`, `/api/products/:id`, `/api/suppliers`
- `GET /api/auth/setup-status`, `POST /api/auth/signup`, `POST /api/auth/login`
- Owner token required: `POST/PATCH/DELETE /api/products`, `POST /api/products/:id/evidence`, `POST /api/impact/estimate`
- Public, rate-limited: `POST /api/ai/insights`, `GET /api/impact/factors`

AI answers use server-retrieved records; arbitrary product data supplied by a browser is ignored. Public AI requests are rate-limited. Review all model output and impact estimates before using them for business decisions.
